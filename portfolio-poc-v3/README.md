# BHSS V3 — Stage 0 test site

Synthetic, local-only prototype. Vite/React calls a layered Express API backed by a separate SQLite database (`data/stage0.sqlite`). It does not import V2 data or provide production authentication. Demo IDs are `superAdmin`, `Admin`, `teacher`, `superTeacher`, `student`, `user`, and `denied`; each uses password `123`. Admin and superAdmin can run CSV imports; teacher, superTeacher, student and user have read-only test access; denied has none. These permissions are synthetic test fixtures, not BHSS policy. Teacher, SuperTeacher and student show a synthetic class 1A; class and teacher management are not implemented. The signed JWT is in an HttpOnly, SameSite=Strict cookie; the request key and revocation state are held in memory. Login revokes the previous browser session; logout revokes and clears it. Restart invalidates all sessions. `V3_SESSION_TTL_SECONDS` controls both JWT and cookie lifetime in seconds (default 3600); change it before starting the server. Refresh restores an active session; logout and expiry require a new login. Set `V3_JWT_SECRET` server-side and `V3_COOKIE_SECURE=true` only when using HTTPS. Use no real school data.

Install with `npm ci`, then `npm run dev`. Open http://127.0.0.1:5180. Sign in as Admin, download the CSV, edit rows, upload, preview and commit. Inspect saved records and the current-session run history. The stage and conflict lists are planning summaries; uploaded records are synthetic and do not approve requirements. Stage 1 and later functions remain planned.

`npm test`, `npm run build`, and `npm run test:e2e` use isolated temporary databases for tests. Set `V3_DB` to select a separate SQLite path. Do not point it at retained or V2 data. Migrations, backup and recovery are required before using retained data.
