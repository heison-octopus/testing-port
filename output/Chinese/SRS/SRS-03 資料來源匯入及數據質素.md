# SRS-03 資料來源、匯入及數據質素

## 1. 目的

匯入校務、Time Infinity、活動、問卷及成績資料，同時保留來源，並避免資料被錯誤配對至其他學生。

## 2. 處理流程

```text
uploaded → parsed → received
received → identity_matched → validated → included_in_assessment
received → needs_identity_resolution → corrected → validated
validated → excluded
activity_catalogue staged → no_change | successor_draft | disabled | restored
```

納入評估不等同向學生發布。

## 4. 匯入格式

| 格式 | 用途 |
|---|---|
| 用戶及班別紀錄 | 建立／更新身份，不包括密碼 |
| 學年、時段及班別 | 建立有日期的學校結構 |
| 活動名單 | 配對學生 ID、預覽姓名、修正暫存列及加入參加者 |
| 活動目錄／修訂 | 匯出可編輯受管制欄位、暫存明確差異、建立後繼草稿，以及在不把缺少列視為刪除的情況下軟停用／恢復穩定活動 |
| 表格定義 | 按 VASK 匯出候選題目、驗證修訂內容、預覽逐行變更及建立後繼草稿版本 |
| 問卷回應 | 老師上載已填結果；經驗證及發布後學生才看見 |
| 學科成績 | CHI/ENG/MATH/LS 或其他設定科目，只作輔助佐證 |
| 外部活動來源 | 保留 Time Infinity 或其他來源擁有權 |
| 外部媒體連接器 | 按媒體識別碼從一個或多個校方認可的儲存位置取得內容，同時保留資料來源及存取規則 |

## 5. 限制及驗證

| 輸入 | 最小值 | 最大值 | 錯誤處理 |
|---|---:|---:|---|
| 每次匯入檔案 | 1 | 1 | 多出的檔案拒絕 |
| 試算表大小 | >0 | 4 MiB | 解析前拒絕 |
| 資料行 | 1 | 5,000 | 說明上限後拒絕 |
| 欄數 | 1 | 100 | 說明上限後拒絕 |
| 欄名 | 1 | 64 個字元 | 必填欄重複／未知時報錯 |
| 儲存格文字 | 0 | 4,000 個字元 | 標示該行，不截斷 |
| 來源紀錄鍵 | 1 | 200 個字元 | 冪等處理必填 |
| 數值成績 | 量表最小值 | 量表最大值 | 未設定量表前不准匯入 |

P0 只接受 `.xlsx` 及 `.csv`。公式只讀取已儲存數值，不執行巨集或可執行內容。

P0 的表格定義只接受 `.xlsx`，檔案最多 4 MiB，最多 200 條題目。這份檔案不包含學生答案，並與回應輸入規格分開處理。

## 6. 權限及鎖定

- 老師只可為獲分配活動匯入名單／答案。
- 職員可處理委派範圍內的例外。
- SchoolAdmin 設定資料來源及權威識別碼。
- SchoolAdmin 或另獲授權的匯入操作人員可暫存及提交全校活動目錄差異，但這項操作權限不等同活動批核權限。
- 活動原始建立人維持不變；目前擁有人、上載／提交人及批核分派須分開記錄及獨立授權。
- 批次提交後原始行不可修改；修正以追加紀錄處理。
- 驗證及發布為兩個獨立步驟。

## 7. 驗收情境

- 預覽在提交前同時顯示輸入的學生 ID 及配對姓名。
- 未知 ID 會暫停處理，可在不改寫原檔下修正。
- 缺少回應會進入老師待辦，不會計作零分。
- 超出指定量表的成績會被拒絕。
- 同一批次重複上載不會產生重複紀錄。
- 排除一筆先前已使用的錯誤資料列時，系統不可靜默改用另一列或另一結果；依賴項目須標記為待覆核。
- 從已匯出 CSV 移除某活動列，再匯入其餘列，不會更改被省略的活動。
- 使用相符預期修訂編號修改重大活動欄位時，系統建立後繼草稿，而最近一個已批核修訂繼續作為正式版本；過時預期修訂須被拒絕。
- 排除暫存的 `disable` 列時，活動維持啟用；只有提交明確 `disable` 才會從學生介面隱藏，同時保留職員審計歷史及依賴佐證。
- 明確 `restore` 會建立新生命週期事件並恢復存取，不會抹去原有停用事件。

## 8. 有版本 Rubric 試算表合約

**狀態：2026 年 10 月 29 日確認的系統分析方向；不代表 BHSS 或 JC 已批准。** Rubric 管理採用一個 `.xlsx` 套件，並固定包含五張互相連繫的工作表：`rubric_catalogues`、`rubric_groups`、`rubric_skills`、`rubric_levels` 及 `rubric_steps`。「匯出全部」須包含範圍內所有實際儲存紀錄及穩定鍵；「新增紀錄範本」是另一個下載，絕不可用示例列代替實際資料。暫存套件只有在外鍵、唯一 ID、申報選取模式、停用標記及階段完整性全部通過驗證後，才可建立後繼草稿。來源路徑／檔名、內容雜湊值、上載者、上載時間、驗證結果、提交人及啟用事件均須可稽核。Rubric 匯入不可永久刪除紀錄，亦不可原地改寫生效版本。

驗收：所提供的 Skills Builder 套件須匯出 4 個組別、8 項技能及 128 個階段定義；重新匯入有效套件會建立新目錄 ID 的草稿並保存 `supersedes_rubric_catalogue_id`；錯誤連繫、不完整分數範圍，或混合／未知選取模式均會阻止提交。
