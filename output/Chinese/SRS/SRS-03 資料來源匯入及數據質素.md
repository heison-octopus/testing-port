# SRS-03 資料來源、匯入及數據質素

## 1. 目的

匯入校務、Time Infinity、活動、問卷及成績資料，同時保留來源，並避免資料被錯誤配對至其他學生。

## 2. 處理流程

```text
uploaded → parsed → received
received → identity_matched → validated → included_in_assessment
received → needs_identity_resolution → corrected → validated
validated → excluded
```

納入評估不等同向學生發布。

## 3. 功能要求

| ID | 要求 | 狀態 | 階段 |
|---|---|---|---|
| IMP-FR-001 | 每次匯入須記錄來源系統、格式版本、檔案雜湊、上載人及時間。 | 已確認架構 | P0 |
| IMP-FR-002 | 正式提交前須先暫存及預覽。 | POC 對齊建議 | P0 |
| IMP-FR-003 | 每行可獨立接納、拒絕或等待身份處理；單一錯誤不可令其餘資料無聲消失。 | 建議架構 | P1 |
| IMP-FR-004 | 原始內容不可改寫；修正另記欄位、前後值、原／新學生 ID、原因、處理人及時間。 | 已確認 M-10 | P0 |
| IMP-FR-005 | 應有而未收到的回應標示 `missing_response`，不可當作零分。 | 已確認 M-11 | P0 |
| IMP-FR-006 | 修正後須重新驗證才可納入。 | 建議架構 | P0 |
| IMP-FR-007 | 重複來源鍵及雜湊須以冪等方式處理，或明確建立新版本，不可重複計算。 | 建議架構 | P1 |
| IMP-FR-008 | 匯入後須可下載錯誤／對帳報告。 | 建議架構 | P1 |
| IMP-FR-009 | 最終欄位及備用身份配對規則仍待確認。 | L-03/L-06 | P1 |

## 4. 匯入格式

| 格式 | 用途 |
|---|---|
| 用戶及班別紀錄 | 建立／更新身份，不包括密碼 |
| 學年、時段及班別 | 建立有日期的學校結構 |
| 活動名單 | 配對學生 ID、預覽姓名、修正暫存列及加入參加者 |
| 問卷回應 | 老師上載已填結果；經驗證及發布後學生才看見 |
| 學科成績 | CHI/ENG/MATH/LS 或其他設定科目，只作輔助佐證 |
| 外部活動來源 | 保留 Time Infinity 或其他來源擁有權 |

## 5. 限制及驗證

| 輸入 | 最小值 | 最大值 | 錯誤處理 |
|---|---:|---:|---|
| 每次匯入檔案 | 1 | 1 | 多出的檔案拒絕 |
| 試算表大小 | >0 | 4 MiB | 解析前拒絕 |
| 資料行 | 1 | 5,000 | 說明上限後拒絕 |
| 欄數 | 1 | 100 | 說明上限後拒絕 |
| 欄名 | 1 | 64 個字元 | 必填欄重複／未知時報錯 |
| 儲存格文字 | 0 | 4,000 個字元 | 標示該行，不截斷 |
| 來源紀錄鍵 | 1 | 200 個字元 | 冪等處理必填 |
| 數值成績 | 量表最小值 | 量表最大值 | 未設定量表前不准匯入 |

P0 只接受 `.xlsx` 及 `.csv`。公式只讀取已儲存數值，不執行巨集或可執行內容。

## 6. 權限及鎖定

- 老師只可為獲分配活動匯入名單／答案。
- 職員可處理委派範圍內的例外。
- SchoolAdmin 設定資料來源及權威識別碼。
- 批次提交後原始行不可修改；修正以追加紀錄處理。
- 驗證及發布為兩個獨立步驟。

## 7. 驗收情境

- 預覽在提交前同時顯示輸入的學生 ID 及配對姓名。
- 未知 ID 會暫停處理，可在不改寫原檔下修正。
- 缺少回應會進入老師待辦，不會計作零分。
- 超出指定量表的成績會被拒絕。
- 同一批次重複上載不會產生重複紀錄。
