# Playground v2 對原始構想的覆蓋評估

**評估日期：**2026 年 10 月 29 日  
**文件狀態：**內部系統分析覆蓋評估  
**原始證據：**`Design ideas.docx` 第 1–6 頁  
**比較對象：**目前本機版本 `portfolio-poc-v2/`

本評估不代表 BHSS 或 JC 驗收，不會把原始構想自動視為已確認需求，亦不會修改 Core 或 SRS。文件只記錄現時 Playground v2 可以實際操作多少原始產品方向。

可選用的本機 LLM 接駁及 AI 覆核狀態保存，是 2026 年 10 月 29 日的內部系統分析實作方向，並不代表 BHSS 或 JC 已批准使用 AI。

## 1. 整體結論

Playground v2 現已示範一條連貫的本機流程，由完整活動資料套件開始，經學生反思、具名同儕互評、教師評估、最難忘活動整理、Portfolio 覆核，直至正式發布檢視。管治、存取控制、不可變修訂及具名批核仍是 POC 的核心，但已不再是唯一有實質覆蓋的部分。

與上一次評估相比，最大改變是加入按角色分開的學習紀錄。活動發布後可建立學生自我回應任務；獲分派教師可建立具名同儕任務、覆核回應、撰寫回饋，以及記錄連繫佐證的 1–16 階段觀察。學生可在獨立流程選擇最難忘活動，再組合 Portfolio 工作版本；正式 Portfolio 只會讀取已批核快照。當伺服器已設定可選用的 OpenAI 相容供應商時，亦可產生連繫來源的學習者敘述候選內容，但模型不會取得評估或發布權限。

原始方向仍有重要部分未完成。V2 現已有共用於 CSV、XLSX 及伺服器端 Time Infinity JSON 測試資料的分階段活動名冊匯入合約，但仍未有媒體／檔案佐證上載、已獲批核的正式 Time Infinity 端點、正式 OCR、語音轉文字、講者辨認、跨系統同步或通知服務。系統雖已有 Skills Builder 觀察，但新觀察尚未經過納入決定、正式結果覆核及發布。具版本表格流程已可操作，但未有表格庫管理，亦未確認已匯入學校實際使用的反思題目。

因此，下列數字只可視為追溯清單，不能換算成完成百分比。「已示範」亦不等於已達正式環境要求、通過安全審批、獲持份者驗收或確立校本政策。

## 6. 原始文件後新增的重要基礎架構

下列 v2 功能具實際價值，但應標示為**內部系統分析架構決定**，不可說成原始文件需求或 BHSS／JC 已批准事項：

- 以學校作為第一層資料隔離邊界。
- 把職銜、可疊加功能角色、權限及工作範圍分開。
- 以科目、部門、班別、教師群組及活動作為權限範圍。
- 明確拒絕優先，以及全校政策覆寫。
- 按教師職銜、角色、權限及範圍搜尋／篩選。
- 把批核資格與具名批核分派分開。
- 分別設定活動、Portfolio 及發布流程。
- 對無人接手或逾期批核工作作升級處理。
- 活動保留穩定身份，重要修改建立不可變的後繼修訂。
- Portfolio 工作版本及不可變正式發布快照。
- 分開學生回應、教師評估、最難忘活動選擇、Portfolio 編輯、Portfolio 覆核及發布檢視紀錄。
- 由伺服器負責活動、回應、評估及 Portfolio 紀錄的深層連結授權。
- 供應商隔離的可選本機敘述生成、凍結來源清單及已保存人工決定。
- 分層 API／資料庫存取邊界及可累加 SQLite migration。
- 英文／繁體中文介面切換。

這些控制令日後佐證流程更安全及更易按校設定；但評估原始構想覆蓋時，不能以管治功能取代尚未建立的學習佐證及評估功能。

## 7. 建議下一個覆蓋切片

**建議——並非已確認需求或持份者承諾：**上一版建議的垂直流程現已有 POC。下一個切片應接通「佐證至正式結果」流程：

> 媒體或作品上載 → 同意及來源驗證 → 佐證監察 → 納入或排除觀察 → Skills Builder 正式結果覆核及發布 → Portfolio 快照或可稽核重新發布

這條流程可處理原始佐證願景與現時 v2 管治之間最大的剩餘差距，亦可證明新接納來源只會在經過具名人工決定後，才影響正式技能結果。

其後建議次序如下：

1. 加入具類型的媒體／作品上載、同意／存取控制、預覽及軟停用。
2. 加入佐證監察、觀察納入／排除決定及影響預覽。
3. 完成一條正式 `MAX-CONFIRMED` Skills Builder 1–16 覆核、發布及重新發布流程。
4. 在已發布 Portfolio 加入跨學段佐證及成長歷史。
5. 以獲批准的端點及具代表性的核對／錯誤樣本取代 Time Infinity 測試資料；其他即時匯入只透過已批准業務合約擴展。
6. 加入反思、評估及欠交佐證的排程提示與升級處理。
7. 只有在同意、私隱、來源記錄、人工覆核及失敗處理政策獲批准後，才接駁正式 OCR 或語音供應商。
